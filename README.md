# radiation-calc — RadCalc

`radiation-lab.com` 우산의 셋째 lab. **방사선 실무 계산기** 묶음이고 `/calc/` 에 산다.

우산 정본은 `aijhmin1031-eng/radiation-lab`, 절차는 `radiation-meter-tester/docs/umbrella-setup.md`.

## 절대 규칙

1. **상수표를 베끼지 않는다 — 공개 원천에서 계산한다.**
   감마상수 Γ 는 핸드북 표가 아니라 `Σ Eᵢ·yᵢ·(μen/ρ)air / 4π` 로 IAEA(방출선)와
   NIST(감쇠계수)에서 직접 계산한다. 값이 우리 것이 되고 **검증도 된다**.
2. **유료 규격 본문을 재현하지 않는다.** ANSI/ANS-6.4.3 의 GP 빌드업 계수표가 여기 걸린다 —
   Berger 2-계수형과 사용자 입력으로 우회한다(`engine/gamma.ts`).
3. **문헌값을 기억으로 적지 않는다.** 이 레포를 세우는 동안 기억으로 적은 기준값 **넷이 틀렸고**
   (Na-22 Γ·Mn-54 Γ·Zn-65 Γ·Pu-241 비방사능) 그때마다 **계산 쪽이 옳았다**.
   테스트의 기준값은 출처가 확실한 것만 쓴다.
4. **면책 없이 결과를 내보내지 않는다.** 공인 교정·시험·차폐설계를 대체하지 않는다.
5. **공개 콘텐츠는 영문.**

## 데이터 원천

| 데이터 | 원천 | 라이선스 |
|---|---|---|
| 반감기·붕괴형식·감마/X선 에너지와 방출강도 | IAEA Live Chart API `rad_types=g` | 출처 표기 |
| 베타 E_max·E_평균·가지 방출강도 | 같은 API `rad_types=bm`·`bp` | 출처 표기 |
| 알파 에너지·방출강도 | 같은 API `rad_types=a` | 출처 표기 |
| 질량감쇠계수 μ/ρ · 질량에너지흡수계수 μen/ρ | NIST **SRD 126**(Hubbell & Seltzer, NISTIR 5632, `doi:10.18434/T4D01F`) | **공용저작물 아님** — 아래 ★★ |

★★ **NIST 를 「public domain」이라 적고 있었다 — 틀린 주장이었다**(2026-09-16, 「인용하는 법」을
쪽에 실으려고 원문 약관을 열어 보다 잡았다). 그 표는 **NIST Standard Reference Database 126** 이고
쪽에 이렇게 적혀 있다 — 「© 1989, 1990, 1996 copyright by the U.S. Secretary of Commerce …
**All rights reserved.** NIST reserves the right to charge for these data in the future.」
SRD 는 **15 U.S.C. §290e** 로 별도 권리가 붙어 미국 정부 저작물의 공용 원칙(17 U.S.C. §105)에서
**벗어나 있다.**
· **제품에 넣어 계산에 쓰는 것**과 **표 자체를 데이터셋으로 재배포하는 것은 다른 층**이다.
  지금 하는 것은 앞쪽이고, 뒤쪽을 하려면 NIST 에 확인할 것(`data@nist.gov` · `nist.gov/srd`).
· IAEA 는 반대로 **명시적으로 허용**한다 — 약관이 데이터의 「use, reproduction and dissemination」을
  장려하고 **상용 제품에서의 사용까지** 허용하며, 조건은 **출처 표기**와
  **「IAEA 가 보증한다고 말하거나 암시하지 않을 것」** 둘이다.
· 서지·조건의 정본은 **`brand.ts` 의 `SOURCE_CITATIONS`** 한 곳이고 `/methods/` 가 그것을 그린다.

**147 핵종** — 감마 96 · 베타 35 · 알파 33, 그중 **감마를 안 내는 것 45종**
(H-3·C-14·Ni-63·Sr-90·Y-90·Tc-99·I-129·Zr-93·Se-79·Po-210·Pu-241/242·Np-237·Cm-245 …).
폐기물·해체·내부피폭에서 실제로 세는 것들이다.

수확 스크립트는 `scripts/harvest.py`(핵종) · `scripts/nist.py`(감쇠계수) · `scripts/fill.py`
(순수 베타·알파 보충). 산출물은 `src/data/` 에 **커밋된다** — 빌드 시점에 외부를 치지 않는다.

★ **수확에서 실제로 밟은 함정 셋** (전부 조용히 틀린 값을 낸다):
- `rad_types=g` 응답에 **X선이 이미 들어 있다.** `x` 를 따로 받아 합치면 Am-241 이 **16배** 튄다.
- 한 요청에 **이성질체 부모가 섞여 온다.** `p_energy` 로 가르지 않으면 Ir-192 가 **+293%**.
  (덤: Tc-99m=142.68 · Ba-137m=661.66 이 이 경로로 정확히 잡힌다.)
- **δ 를 데이터에 구워 넣지 말 것.** 선을 20 keV 에서 잘라 저장했더니 화면의 δ 손잡이가
  아무 일도 못 했다. 선은 1 keV 까지 싣고 **δ 는 계산 시점에** 건다.
- **이성질체는 베타·알파에도 섞인다** — Kr-85 에 Kr-85m(T½=4.48h)의 840 keV 가 붙어
  E_max 가 **+22%** 틀렸다. `p_energy` 필터를 **세 rad_type 전부에** 걸어야 한다.
  지키는 것은 `data.test.ts` 의 **방출강도 합 ≤105%** 검사다(섞이면 합이 먼저 튄다).
- **NIST 쪽은 같은 표를 두 번 낸다**(인쇄용이 따라붙는다). 자르지 않으면 표가 두 벌이 되고
  **보간은 앞쪽에서 끝나므로 값이 맞고 조용하다** — 에너지축 단조성 검사로만 드러난다.
- **`gamma_const > 0` 으로 방출을 가르지 말 것** — Fe-55·Ge-68 처럼 광자가 전부 δ 아래인
  EC 핵종이 **통째로 사라진다**. 오염검사에서 실제로 세는 것들이다.

## 검증 상태 (`npm test` 69건)

| 항목 | 결과 |
|---|---|
| NIST 감쇠계수 5점 | 문헌과 **0.5% 이내** (662 keV 는 표점 사이 보간이라 1.5%) |
| Γ — Cs-137·I-131·Cs-134·Co-60·Ir-192 | 문헌과 **2% 이내** (δ=20 keV) |
| 비방사능 — Co-60·Cs-137·Pu-239·U-238·Am-241·Sr-90·H-3 | 문헌과 **1% 이내** |
| β E_max — H-3·C-14·P-32·S-35·Ca-45·Ni-63·Sr-90·Y-90·Tc-99·Pm-147·Cl-36·Tl-204·Kr-85·Pu-241·I-129 | **1% 이내** (15/15) |
| α 주선 — Am-241·Pu-239·Po-210·U-238·Ra-226·Cm-244·Pu-238·Th-230 | **0.01% 이내** (8/8) |
| 붕괴·역산·Bateman·MDA·스캔 MDC·단위환산·역제곱·비정·제동복사 | 해석해·경험식과 일치 |
| 데이터 무결성 (이성질체 혼입·표 중복·EC 분류·δ 보존) | 게이트 8건 |

★ **δ=20 keV 가 저에너지 방출체의 답을 좌우한다** — δ=10 으로 두면 Am-241 이 **+805%** 틀린다.
캡슐에 흡수되어 거리에서 선량에 기여하지 않는 광자를 빼는 관행이고, **화면 손잡이로 노출한다**.

## 방문 집계 — 플랫폼 층이고, 이 레포는 한 줄만 든다 (2026-09-15)

소유주 지시로 lab 넷 전부에 방문 집계를 세웠다. **정본은 우산 저장소**
(`aijhmin1031-eng/radiation-lab`)의 `public/track.js` 한 벌이고, lab 넷이 **같은 파일**을 읽는다.
경위·스키마·utm 낱말 규약은 **그 레포 README 가 정본**이다.

이 레포가 든 것은 `src/layouts/Base.astro` 의 한 줄이다 —

```astro
<script is:inline src="/track.js" data-lab="calc" defer></script>
```

· ★★ **`base` 를 붙이면 안 된다.** `/calc/track.js` 는 **없다** — 그것은 우산이 오리진 루트에
  두는 파일이다. base 를 붙이면 **404 가 나고 빌드는 통과하며 집계만 조용히 죽는다.**
  그래서 `is:inline` 으로 Astro 가 손대지 못하게 둔다.
· ★ **게이트 둘을 손봤다**(둘 다 이 변경을 **옳게** 막고 있었다) —
  ① `gate/check-output.mjs` 의 `EXACT_OK` 에 `/track.js` 를 더했다. base 밖을 가리키는 것이
     **맞는** 자리다(「있을 법한 주소」가 아니라 **우산 저장소에 실재하는 파일**이다).
  ② `gate/check-render.mjs` 의 로컬 서버가 `/track.js` 에 **200 을 답한다.** 그전에는 404 라
     **전 쪽에서 「JS 오류」로 세어져 게이트가 통째로 빨개졌다.** 무시하지 않고 **흉내 낸다** —
     「없는 것을 못 본 척」은 태그가 사라져도 통과하지만, **배포 구조를 재현하는 것**은 안 그렇다.
· ★ **공유 줄에 utm 을 달았다**(`ShareRow.astro` 다섯 자리 전부, **「링크 복사」 포함**).
  referrer 만으로는 「어디서 왔는가」가 안 나온다 — 앱 내 브라우저는 referrer 를 비워 보내고,
  메신저·이메일로 옮겨 붙인 링크는 원래부터 없다. **낱말은 우산 README 가 정본이다.**
· 쿠키·localStorage 를 쓰지 않는다(순 방문자는 서버측 일일 해시) — **동의 대상이 아니다.**
  그래서 이 lab 에 동의 배너를 새로 세울 필요가 없었다.
· 보고서는 **`radiation-lab.com/stats/`** 다(로그인 + 우산 DB 의 `rl_admins` 에 든 계정).

★ **`*.vercel.app` 으로 직접 들어온 방문은 세어지지 않는다** — 그 오리진에는 `/track.js` 가
없다. 정본 주소가 우산이므로 그것이 맞는 동작이다.

## ★★ 껍데기는 플랫폼 정본이다 — 이 lab 의 팔레트가 한 칸 밀려 있었다 (2026-09-16)

같은 날 두 번 손댄 자리다. **앞 판의 진단이 절반만 맞았다** — 아래에 경위를 남긴다.

**① 오전** — 소유주 지적 「여기는 메뉴와 본문 배경색이 비슷해보여」. 머리글이 `bg-panel`
(순백)이라 본문(251,251,250)과 채널당 4밖에 차이가 없었다. 머리글 전용으로
`--c-chrome`(241,242,238)을 **새로 만들어** 붙였고, 「껍데기는 본문이 밝으면 어둡게 —
방향이 lab 마다 다른 것이 정상」이라고 적었다.

**② 오후** — 소유주 지적 「radcalc과 radimeter lab 화면 배경색 구성이 다르네 … 상단메뉴는
동일한 배경, 폰트, 크기를 사용하면 좋겠어.」 **①의 그 문장이 틀렸다.**

| | 본문 | 머리글 | 관계 |
|---|---|---|---|
| 우산 | 232,234,230 | 241,242,238 | 머리글이 **밝다** +25 |
| RadiMeter | 232,234,230 | 252,252,250 | 머리글이 **밝다** +58 |
| 이 lab (①의 결과) | **251,251,250** | 241,242,238 | 머리글이 **어둡다** −31 |

· ★★ **원인은 색이 아니라 토큰 이름이 한 칸씩 밀린 것이었다.** 우산·RadiMeter 는
  `paper`=본문 · `surface`=카드 · `panel`=머리글인데, 이 lab 에는 **`--c-paper` 가 없어**
  `--c-surface` 가 본문을 맡고 `--c-panel` 이 순백 카드였다. ①에서 **우산과 같은 값을
  골랐는데도 방향이 반대가 된 이유**가 그것이다.
· ★★ **그래서 값이 아니라 이름을 맞췄다.** `--c-paper` 를 세워 본문에 주고, 카드·입력칸·
  단추를 `--c-surface` 로, 머리글·꼬리말·압축 고정 바를 `--c-panel` 로 옮겼다.
  **`--c-chrome` 은 없앴다** — 머리글 색의 이름은 플랫폼 어디서나 `--c-panel` 이다.
  값만 맞추면 다음 사람이 `bg-panel` 을 「카드 색」으로 읽고 다시 어긋난다.
· ★★ **바탕을 옮기면 글자 대비가 함께 움직인다.** 본문이 251 → 232 로 어두워지며
  `--c-ink-faint` 가 **4.86 → 4.16 으로 떨어졌다**(AA 하한 4.5). 색은 그대로 두고 바탕만
  옮기면 **빌드도 통과하고 눈으로도 안 보이는 채로 접근성이 깨진다.** 101,105,114 로
  내렸다(본문 4.54 · 머리글 4.89 · 카드 5.36). **팔레트를 옮길 때는 대비를 다시 계산할 것.**
· **칸 폭도 맞췄다** — `max-w-content` 를 72rem(1152) → **1048px**, 좌우 여백 16 → 32px
  (모바일 20px). 그전에는 글줄이 좌측 **80px** 에서 시작해 우산·RadiMeter(둘 다 148px)와
  어긋났다 — 오리진을 넘나들면 본문이 68px 왼쪽으로 튀었다.
· **메뉴 칸도 맞췄다** — 13px · w400 · 모서리 4px · 안여백 6·12px · 활성은 앰버 알약.
  ★ `rounded-lg` 는 이 lab 에서 8px, RadiMeter 의 체계에서는 4px 이다 — **같은 클래스
  이름이 두 배 다른 값**으로 풀린다. 이름이 아니라 **값**을 맞춘다.
· ★ **머리글·고정 바가 같은 목록을 읽는다.** 그전에는 링크가 두 곳에 복사돼 있었고
  그 바람에 **`Saved`·`Methods` 에 활성 표시가 아예 없었다**(`/methods/` 에서 켜지는 칸 0개).
· ★★ **「층 대비 18 이상」 검사가 이것을 못 봤다 — 그것은 상대값이다.** 갈리기는 갈리는데
  **서로 다른 방향으로** 갈렸으므로 셋 다 통과했다. 새 게이트 `gate/check-platform.mjs` 는
  **절대값**을 잰다(본문·머리글·아래선·칸 좌측·칸 치수·활성 알약, 라이트/다크).
  역테스트 둘로 확인했다. 정본 값은 우산 README 「껍데기는 플랫폼 정본 한 벌이다」 절이다.
· ★ **교훈**: 「방향이 lab 마다 다른 것이 정상」처럼 **차이를 설명해 버리는 문장**을 조심할 것.
  ①에서 그 문장을 적는 순간 이 결함은 **문서에 의해 정당화**됐다.

### 스펙트럼 반가층 — `src/engine/spectrum.ts`

★★ **반가층은 스펙트럼에 걸린 값이다.** 선이 여럿이면 각자 다른 μ 로 줄고, 얇은 층에서
연한 선이 먼저 죽어 투과곡선이 **단일 지수가 아니다**(빔 경화). 그래서 「대표 에너지의 반가층」은
근사이고, 실무가 쓰는 값은 **「이 핵종의 공기커마율을 절반으로 만드는 두께」**다. 우리는 IAEA 선 표와
NIST μ/ρ 를 둘 다 들고 있으므로 그것을 이분법으로 직접 푼다.

· **실측으로 확인한 것**(`src/engine/spectrum.test.ts`, 10건) —
  **Mn-54**(834.85 keV 한 선이 커마의 100%)에서 해석해와 **오차 0**.
  **Na-22** 는 주선(1275 keV)이 커마의 55% 뿐이라 주선으로 읽으면 납 10.5 mm, 스펙트럼으로 풀면
  **6.5 mm** — **38% 차이**다. 이 차이가 우리가 스펙트럼을 푸는 이유이고, 게이트가 **그 차이가
  있다는 것**을 잰다(사라지면 이유도 사라진 것이다).
· **Sn-113 은 TVL/HVL 이 84 다.** 단일선이면 이 비가 정확히 3.3219 인데, 첫 반가층은 연한 광자를
  죽여 얻고 십가층은 단단한 꼬리를 뚫어야 한다. **「반가층을 세 번 겹치면 1/8」이 거짓**인 핵종이
  있다는 뜻이고, 낱장이 그 비를 인쇄해 독자가 알아보게 한다.
· ★★ **좁은 빔이다 — 문헌표와 다른 것이 정상이다.** Co-60 납 반가층이 우리 값 10.35 mm, 흔히
  인용되는 값 12.5 mm 인데 **틀린 것이 아니라 다른 양**이다(저쪽은 축적 포함). 문헌표에 맞추려
  들면 축적을 몰래 섞게 되고 화면의 「narrow beam」이 거짓이 된다. 그래서 테스트는 문헌표가 아니라
  **같은 정의의 해석해**와 대조한다. 축적 계수는 이 레포가 싣지 않으므로(유료 규격 본문)
  설계값이 필요하면 감마 차폐 계산기에서 계수를 넣는다.

### 147장을 한꺼번에 늘리는 것이 이 작업의 유일한 진짜 위험이었다

★★ **어수 검사는 「틀에 값만 갈아 끼운 글」을 못 본다.** `check-output` ⑥ 은 250어 하한만 보는데
**되풀이되는 설명으로 채워도 어수는 늘어난다.** 첫 판이 정확히 그랬다 — 어수는 최소 346어로
넉넉했지만 낱장 사이 5-그램 겹침이 **중앙 20.8%** 였다. 원인은 분명했다:
「narrow beam 이란 무엇인가」·「왜 저Z 로 막는가」 같은 **설명을 147번 되풀이**하고 있었다.

· 규칙을 세웠다 — **낱장의 문장은 「이 핵종의 숫자」와 「그 숫자에서 나오는 판단」만** 담는다.

· **쪽마다 다른 척하는 숫자를 쓰지 않는다** — 제동복사 수율의 「몇 배」는 Z 비율(82/6)이라
  **모든 핵종에서 같다.** 그런 숫자를 147번 찍는 것이 정확히 틀에 값만 갈아 끼우는 짓이다.
· 지키는 것은 **`node gate/check-nuclides.mjs`**(CI 포함). 겹침 중앙 상한 18% · 한 쌍 상한 55%.
  역테스트로 확인했다 — 설명을 되돌리자 **27.8%** 로 걸렸다.

### 게이트가 자기가 아는 것만 보던 구멍

★★ 처음에 계산기 링크를 **`?n=Co-60`** 으로 적었는데 **그것을 읽는 코드가 아무 데도 없었다**
(상태는 `?s=<base64 json>` 하나로만 들어온다). 눌러도 기본 핵종이 뜬다 — 이 lab 이 `Saved` 에서
이미 밟은 「없는 기능을 광고하지 않는다」와 같은 종류다. 지금은 `encodeState` 와 같은 꼴을
빌드 시점에 만들고, **브라우저로 눌러 값이 실제로 복원되는지** 게이트가 확인한다.

★★★ 그런데 **역테스트에서 게이트가 그 회귀를 놓쳤다.** 처음 판은 「`?s=` 가 있는 링크」를 세었는데,
죽은 `?n=` 링크는 그 패턴에 안 걸려 **검사 대상에서 빠지고 통과했다.** **검사가 자기가 아는 것만
보면 고장난 것은 늘 시야 밖에 있다.** 지금은 링크에 **`data-prefill` 표식**을 달고 표식을 세며,
표식 없는 **내부** 링크가 질의인자를 달고 있으면 그 자체를 결함으로 센다.
(★ 처음에 링크 전부를 봤다가 **공유 단추(X·Threads·LinkedIn)가 걸렸다** — 그쪽 인자는 남의
서비스가 읽는 것이다. 내부만 본다.)

· ★★ **목록 표에서 같은 자리를 두 번 밟았다**(둘 다 소유주가 화면에서 잡았다).
  ① 148행 × 6열이 390px 에서 문서를 **269px 넘겼다** → 스크롤 컨테이너에 넣었다.

     남는 것은 「beta-minus decay · beta · —」뿐이고 **그 줄은 아무 뜻이 없다.**

    좁은 화면에서 이 목록의 일은 **찾아서 누르는 것**이고, 셋은 낱장 맨 위에 다 있다.
    실측: 360·390·700·900·1024·1280px 전부 **가로 스크롤 0**. 320px 만 27px 남고
    거기서는 고정 칸이 일을 한다.

    `check-nuclides` ⑥ 이 일곱 폭에서 ① 흔한 폭에 스크롤이 없는가 ② 스크롤이 생기는 폭에서
    끝까지 밀어도 첫 칸이 보이는가를 잰다. 역테스트 둘로 확인했다
    (고정을 떼면 320px 에서, 칸을 다 보이게 하면 360·390·700px 에서 걸린다).

    목록 표의 첫 칸은 `left: 0` 으로 붙고 `top` 은 `auto` 인 것이 **맞다**. CI 가 148행을
